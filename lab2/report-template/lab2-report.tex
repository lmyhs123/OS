\section{实验内容与实现}

\subsection{物理内存初始化 page\_init}

接口 \nolinkurl{static void page_init(void)} 无参数、无返回值，通过全局量 pages、npage 和 va\_pa\_offset 提供结果。


\begin{enumerate}
\item 验证 DTB 的 base、size、加法溢出；当前框架 page2ppn 固定使用 DRAM\_BASE，因此明确拒绝其他基址，避免悄悄错误映射。

\item 设置 va\_pa\_offset，取设备树上界和 PHYSICAL\_MEMORY\_END 的较小值，再向下按 4096 字节对齐。

\item npage 是管理上界的绝对物理页号，不是 RAM 页数；描述符数量为 npage-nbase。

\item 将描述符数组放在链接符号 end 之后并按页向上对齐，先检查整个数组能否放入受管 RAM；每个描述符先标 reserved、ref=0。

\item 空闲起点放在描述符数组之后，向上对齐。保留 OpenSBI、内核及元数据。当前 DTB 在 RAM 顶部附近，为避免覆盖，保守保留从 DTB 所在页至管理上界的尾段；这是安全但可能浪费部分内存的策略。

\item 仅当存在完整空闲页时调用 init\_memmap。框架要求 n>0，因此没有空闲整页时不调用它。

\end{enumerate}
默认 128 MiB RAM 实测：管理区间 [0x80000000,0x88000000)，npage-nbase=32768，sizeof(Page)=40；描述符 PA=0x80207000；完整空闲页区间 [0x80347000,0x87e00000)，共 31417 页。64 MiB 实测自动缩小管理上界；256 MiB 实测按框架 0x88000000 上界裁剪。评分脚本关于 npage 的预期针对默认内存，不能把默认 20/20 推广为任意内存配置的评分结论。


\subsection{First-Fit 的理解及改进}

default\_init 初始化双向链表和空闲计数；init\_memmap 将可用区间组成块，头页 property 保存块长。alloc\_pages 从链表头开始选第一块长度\ensuremath{\geq}n 的块，分割余块；free\_pages 按地址插入，并与前后物理相邻块合并。


查找时间最坏 O(空闲块数)，地址有序链表便于合并，但不保证最小碎片。可使用分桶、平衡树、位图或最近搜索位置改善搜索成本；也可减少频繁分割。不能保证任何策略都能消除外部碎片。


\subsection{Best-Fit}

复用框架约定的地址有序空闲链表；遍历所有满足 property\ensuremath{\geq}n 的块，选择 property 最小者。同长时保留首先遇到的低地址块。分配后移除原头、为剩余块设置新头，减少 nr\_free；释放时插入并合并相邻空闲块。init\_pmm\_manager 默认选择 best\_fit\_pmm\_manager。


修正了复制参考链表插入逻辑时的尾插入风险：尾部插入后必须 break，否则循环可能继续访问刚插入的节点甚至重复插入。除课程原测试外，增加32页隔离池测试：分配32个单页、耗尽返回NULL、释放偶数页形成碎片时不能分配2页、释放奇数页后重新合并成32页，最终计数恢复。


原 basic\_check 与 best\_fit\_check 内容保持不变；新增 best\_fit\_verify 包装调用二者之外的附加测试。普通运行和注入评分都真正使用 Best-Fit。改进可采用按长度索引的树/分桶，同时保留按地址合并结构；当前线性查找为 O(k)，仍可能制造小碎片。


\subsection{Buddy System}

新增 buddy\_pmm.c/h，使用0到15阶空闲链表，每阶块大小为2\textasciicircum{}order页。初始化把任意长度初始区间拆成物理页号对齐的二次幂块。申请 n 页向上取整到最小二次幂，从足够大的一阶拆分；伙伴页号由 ppn XOR (1<<order) 得到。释放仅合并同阶、真正的伙伴，不能仅凭地址相邻就合并。


alloc\_pages(3) 实际占4页，free\_pages 必须使用原始申请长度3，以同样的阶数释放。各阶头标记由 PageProperty 与 property 保存；available 统计实际剩余页数。构建 \nolinkurl{make PMM=buddy} 时切换管理器，切换前必须 make clean，避免复用另一配置的目标文件。


测试覆盖：零长度和超最大阶请求、3页向4页取整、4页/8页对齐、并存块无重叠、释放前后计数恢复；隔离一个8页块，拆成8个单页至耗尽，逆序释放，重新申请8页必须恢复原块。这能检查分裂、伙伴合并和计数，而不仅是“申请返回非空”。


\subsection{简化 SLUB 对象分配}

新增 kmalloc(size\_t n)、kfree(void *p)、slub\_check()。这是体现 SLUB 主体思想的单CPU教学实现，不等同于 Linux 生产级 SLUB。


下层使用当前 pmm\_manager 的页分配；上层提供16、32、64、128、256、512、1024字节七种缓存。每个slab一页，页首为元数据，后面切分为固定长度对象；空闲对象首部存放下一个空闲对象指针。对象16字节对齐。超过1024字节走连续页大对象路径，申请页数为 ceil((header+n)/4096)，最大接受1 MiB。大对象仍保留首部元数据，使 kfree 能还原页及长度。


kfree(NULL) 无操作。释放小对象时检查页头、位置、对齐及重复释放，把对象放回空闲链；整slab空闲后从缓存链移除并归还底层页。Buddy 模式下底层页请求可能取整，但仍保存原请求页数，以相同请求释放。


测试覆盖各大小类边界1/16/17/32/33/.../1024/1025、4096和9000字节，逐字节写入和核对防止重叠，逆序释放后空闲页计数恢复；300个32字节对象跨多个slab，验证数据、同一可用slab中的对象复用及所有页回收。早期测试错误假定任意slab释放的对象都是下次首选；改为释放当前优先缓存slab中的对象后检验复用，没有修改分配策略以迎合错误假设。

\section{分支任务：实际调试 QEMU 的 MMU 路径}

\subsection{调试架构}

客体 gdb-multiarch 经 QEMU stub 观察 RISC-V 寄存器和内核；宿主普通 gdb 运行 x86-64 的 QEMU 进程，断点落在其C源码。宿主GDB作为QEMU父进程，不需要sudo attach，也避免ptrace限制。QEMU调试版位于 /home/lmy/oslab-tools/qemu-ubuntu-build/qemu-system-riscv64，源码在相邻qemu-source。具体复现脚本见 tools/verify\_guest.py、tools/verify\_host.py，交互命令见 docs/演示命令.md。


\subsection{SATP 与大页的客体观察}

实测 SATP=0x8000000000080205：MODE=8表示Sv39，ASID=0，根表PPN=0x80205，即物理地址0x80205000。根表第511项位于0x80205ff8，PTE=0x200000cf；恒等映射第2项也为相同PTE。


PTE的PPN=0x80000，对应PA基址0x80000000；低位0xcf表示V/R/W/X/A/D为1、U/G为0。根表叶子映射1 GiB。三级页表是最多三级查询，遇到叶子可提前结束。本实验两项覆盖低地址0x80000000起1 GiB，以及高地址0xffffffffc0000000起1 GiB。真实受管RAM只有其中一部分，大页映射范围不等于可分配RAM范围。


\subsection{宿主断点与真实翻译}

选择既会取指的kern\_init，又会读取数据的boot\_dtb做两次独立运行。宿主条件断点位于 riscv\_cpu\_tlb\_fill、get\_physical\_address、PTE读取后的分支和tlb\_set\_page前。is\_debug=0用于排除调试器自身的内存查询。


实测关键行（完整输出见 evidence/host-console.log 与 host-data-console.log）：


\begin{lstlisting}
WALK_ENTER addr=0x80200000 satp=0 is_debug=0
WALK_ENTER addr=0xffffffffc02000d6 satp=0x8000000000080205 is_debug=0
PTE_READ ... i=0 ptshift=18 base=0x80205000 pte_addr=0x80205ff8 pte=0x200000cf
TRANSLATED VA=0xffffffffc02000d6 PA=0x802000d6 prot=7 cached_size=0x1000
TLB_MISS address=0xffffffffc0206008 access=0 mmu_idx=1
TRANSLATED VA=0xffffffffc0206008 PA=0x80206008 prot=7 cached_size=0x1000
\end{lstlisting}

取指access=2，数据读取access=0，mmu\_idx=1对应此次S模式访问。数据读调用栈真实出现 do\_ld8\_mmu \ensuremath{\rightarrow} mmu\_lookup \ensuremath{\rightarrow} mmu\_lookup1 \ensuremath{\rightarrow} tlb\_fill \ensuremath{\rightarrow} riscv\_cpu\_tlb\_fill。


\subsection{页表遍历与TLB原理}

QEMU 8.2的 target/riscv/cpu\_helper.c 中 get\_physical\_address 先检查权限模式和SATP模式；本次Bare阶段直接使用原地址。Sv39时以根表物理地址为base，计算当前层index和pte\_addr=base+index*8，使用address\_space\_ldq读取8字节PTE，再检查合法性。V=0失败；R/W/X有叶子权限则转到leaf；否则提取PPN，将base更新为下级表物理地址，继续循环。因此循环的职责是层级遍历，不是重复猜地址。框架顶层即为叶子，所以这次循环i=0时结束。


此处ptshift=18是还要保留的下级VPN位数，两层各9位，共18位；不是虚拟地址总偏移。1 GiB叶子的物理地址由PPN高位、虚拟地址的低级VPN和12位字节偏移组成，等价于 PA=0x80000000+(VA \& 0x3fffffff)。对数据读得到0x80206008。


软件TLB查找位于accel/tcg/cputlb.c。mmu\_lookup1读取并比较TLB标签，不命中时先尝试victim\_tlb\_hit，再通过tlb\_fill调用架构的riscv\_cpu\_tlb\_fill；成功后tlb\_set\_page缓存结果。取指另由get\_page\_addr\_code\_hostp/probe\_access\_internal路径进入。get\_physical\_address不是每次访问必经函数：命中缓存时可以绕过页表遍历，TCG翻译块缓存也会影响取指路径。


QEMU软件TLB承担客体地址转换及访问权限缓存，并保存加速宿主访问需要的信息；它不等于实体RISC-V处理器某一型号的硬件TLB，也不等于宿主x86 CPU自己的TLB。本次大页翻译虽然使用1 GiB叶子，软件缓存填充实测cached\_size为0x1000，不能把二者混为相同页大小。进入内核前Bare模式虽然不做Sv39遍历，QEMU仍可能调用软件TLB填充，这正是日志中SATP=0时也有TLB\_MISS的原因。

\section{总结、理论联系与扩展思考}

页级分配器解决“哪些连续物理页可以使用”，SLUB解决“如何把页切成对象”，页表解决“CPU地址如何翻译”，TLB解决“如何缓存翻译”；这些是不同层次。reserved防止把固件/内核/描述符作为空闲内存发出；property只在空闲块头解释，不能拿任意页的值当块长。


未知硬件RAM范围可通过DTB、UEFI内存映射或平台固件协议获取，并结合保留区域及硬件窗口；本框架DTB解析只识别一个memory节点的reg，不应盲探任意物理地址，也不宣称支持多段RAM和完整reserved-memory语义。未来可扩展多个物理区间、FDT保留表与启动参数保留区。


本实验尚未实现进程地址空间隔离、按需分页、页面置换、系统调用、调度、文件系统，以及多核/中断环境下的分配器同步。过渡恒等映射和宽权限1GiB启动页适合教学启动，不是最终内核应长期采用的最小权限布局。


本次实验证明了可管理物理页建立、Best-Fit接入、Buddy和对象分配，以及QEMU中真实地址转换的关键路径。答辩命令、参数解释和追问见docs目录。
