# Lab2 从零理解：做了什么、为什么、参数与答辩追问
> 本文面向零基础阅读。CPU是执行指令的处理器；RAM是程序运行使用的内存；内核是操作系统管理资源的核心程序。遇到缩写、函数名或位运算，可查文末“全部术语解释”，无需预先背英文。

## 1. 先记住一句话

Lab1让内核“跑起来并输出”；Lab2让内核“知道哪些内存可以用、按页分配、按对象分配，并看清CPU地址如何变成物理地址”。物理页分配器、对象分配器、页表、TLB是四个不同层次。

假设RAM是一栋楼：物理地址给每个字节编号；物理页把它切成4096字节一间的房；Page描述符是管理每间房的登记卡；页分配器分整间房；SLUB把房间划成小柜子给小对象；页表负责把程序看到的地址指向实际房间；TLB保存最近查过的映射。登记卡本身也要占内存，所以先保留它们，不能把登记卡所在房间再次发给别人。

## 3. page_init：先造登记卡，再发空房间

### 地址和页号

一个页有4096字节，所以页号PPN=PA>>12，PA=PPN<<12。页内偏移是地址低12位。`PGSIZE=4096`是页大小，`PGSHIFT=12`是4096=2^12的指数。

`nbase=0x80000000/4096=0x80000`是DRAM起始物理页号。默认128MiB时，管理上界0x88000000，`npage=0x88000`。注意npage不是32768；`npage-nbase=0x8000=32768`才是页数。

`pages[i]`是第i个登记卡，对应PA=0x80000000+i*4096。`page2pa(p)`从卡片地址算物理地址；`pa2page(pa)`从物理地址算卡片地址。`Page*`指向元数据，不是指向那个物理页本身。

### 虚拟地址

内核以高地址运行，`VA=PA+0xffffffff40000000`。例如PA=0x80200000对应VA=0xffffffffc0200000。页表让CPU把这个高地址翻译回真正的物理地址。

PHYSICAL_MEMORY_END=0x88000000是框架管理上界，不是永远等于DTB真实上界。小RAM取设备树更小的上界，大RAM最多管理到框架上界。ROUNDUP把起点向上对齐，防止覆盖上一页占用；ROUNDDOWN把终点向下对齐，防止把不完整尾页算进去。

### 描述符里的参数

`ref`是引用计数，本实验初始化为0；`flags`是位标记，reserved表示不能分配，property表示空闲块头；`property`在Best-Fit头页表示块长，在Buddy头页表示阶数，因此不能跨管理器解释。`page_link`把卡片连接成双向链表，链表头是管理结构，不对应一个可分配页。

默认sizeof(Page)=40；32768个描述符占1310720字节，即320页。数组从PA=0x80207000开始，到0x80347000结束。空闲区还避开DTB尾段，所以得到31417页。空闲计数小于总页数是正确结果，不能把固件、内核与元数据算成空闲。

当前DTB解析器只取一个memory节点的reg，尚未遍历所有保留表。我们保守保留DTB页到RAM顶的尾段；这不是最省内存的通用解析器，但避免实际DTB被分配覆盖。

## 4. Best-Fit：从够大的块里选最小的

例：空闲块分别有10、6、20页，请求5页。First-Fit会拿第一个10页块；Best-Fit遍历后拿6页块，留下1页。它减少这次选择的余量，但不保证全局最优，留下的小块仍可能不好用。

`alloc_pages(n)`的n单位是页，不是字节；返回块头对应的Page卡片。申请失败返回NULL。`free_pages(base,n)`的base是卡片指针，n是归还页数。`nr_free_pages()`表示总空闲页，不表示最大连续块长；总共还有10页但分成10个不相邻单页时，申请2页仍会失败。

分割时新头=old+n，长度=old_length-n。释放时先插入地址有序链表，再检查 `previous+previous_length==base` 与 `base+length==next`。等式用Page指针相加，描述符连续且按物理页顺序对应，因此能判断物理页是否连续。

为什么尾插后break？链表已经变了，如果继续循环，新节点也可能被遍历并重复插入。附加32单页交错释放测试可以专门触发尾插与碎片合并，而不是只靠原有测试通过。

## 5. Buddy：把块限制成二次幂

阶order表示块含2^order页，不是2^order字节。order=0一页，order=3八页。MAX_ORDER=15上限为32768页，与当前管理规模匹配。

请求3页向上取整为4页。这浪费一页，称内部碎片；好处是块结构规整，容易定位伙伴和快速分裂合并。假设某块起始PPN=8，order=2，伙伴PPN=8 XOR4=12，两块合并成从8开始的8页块。地址相邻但不满足同阶伙伴关系不能合并。

初始化的空闲区未必是二次幂、也未必天然大块对齐，因此逐段找既能放下又对齐的最大阶块。不能直接把整片空闲区当作一个Buddy块。

申请时找到最近一个非空的较大阶，反复一分为二，把一半留下；释放时同阶伙伴在空闲表中才能递归合并。`available`记录实际空闲页，因此3页请求会减4。释放必须使用原请求长度，不支持随意释放已分配块内部一部分。

## 6. SLUB：让几十字节对象不用独占4096字节

页分配器最小粒度4096字节，给24字节对象整页会浪费很多。简化SLUB把一页切成固定大小对象，24字节请求进入32字节类；同大小对象共享缓存。

缓存大小16..1024是本次设计选择，不是RISC-V硬件规定。16字节对齐是本实现提供的约定；头部也向16对齐。单页容量floor((4096-header)/unit)，页头保存magic、next、free、unit、used、capacity、page、npages。magic识别元数据；used是已分配对象数；capacity是对象容量；page/npages用于最后归还页。

空闲对象内部暂存next指针，因为空闲对象当前不承载用户有效内容；分配后用户可以覆盖它。大小类至少16字节，足够放8字节指针。释放时把对象重新挂回链表；used归零时回收整页。

对象>1024请求连续页，首部保存分配信息；`ceil((header+n)/4096)`考虑了首部，不能只按n计算。最大1MiB是防止无界请求的教学限制。此实现没有多核per-CPU cache、无锁快路径和复杂调试机制，不应称为完整Linux SLUB。

## 7. Sv39与这次实际出现的巨大叶子

Sv39的有效地址结构是9位VPN2、9位VPN1、9位VPN0和12位页内偏移，共39位；64位寄存器中高位应符号扩展。每表4096字节，8字节一项，所以每张表512项。

SATP高4位MODE=8表示Sv39，中间ASID=0，低44位是根表PPN。实测0x8000000000080205，因此根表物理地址=0x80205<<12=0x80205000。

高地址索引VPN2=(VA>>30)&0x1ff=511。根表项地址=0x80205000+511*8=0x80205ff8。PTE=0x200000cf：PPN=PTE>>10=0x80000；低位V=1有效、R=1可读、W=1可写、X=1可执行、U=0非用户页、G=0非全局标记、A=1已访问、D=1已脏。预设A/D避免该启动映射首次访问时要求更新它们。

根表就设置R/W/X，说明它是叶子，映射1GiB；如果仅V=1而R/W/X为0，才指向下一级。Sv39规定最多三级，不能说每次都走三级。本次VA=0xffffffffc0206008的低30位为0x206008，因此PA=0x80000000+0x206008=0x80206008。

### 写SATP后为什么先死住？

原入口只有高地址映射。写satp时CPU还在低地址0x8020...执行，下一次取指也需要翻译；低地址没有PTE，就可能发生取指页故障。我们在根表第2项也设置相同1GiB叶子，使低地址与高地址暂时都映射RAM，完成sfence.vma和高地址跳转。之后内核运行在高地址。这个过渡映射可在更完善内核中移除，但本次保留以便教学观察。

`sfence.vma`要求后续翻译与新的页表状态一致，通常可理解为相应TLB失效；它不是清除全部RAM数据，也不是清CPU所有缓存。

## 8. 两层GDB到底各调什么

客体GDB看到RISC-V的pc/sp/satp与内核源码；宿主GDB看到x86-64 QEMU进程的C函数、局部变量与调用栈。宿主暂停QEMU时，客体GDB请求得不到回复是正常的，因为负责响应的QEMU也被暂停了。要先在宿主continue，才可继续驱动客体。

GDB读取内存也会请求地址翻译，因此条件里检查is_debug=0，保证关注实际执行访问。取指日志access=2；boot_dtb数据读access=0、size=8，调用栈有do_ld8_mmu，因此证据不只包含指令取指，也包含数据读取。

软件TLB查找先比较标签；miss尝试victim，再调用架构翻译。get_physical_address每次处理一次翻译，不是每条指令的公共入口。若表项非叶子，取出下一级PPN继续；若叶子，检查权限和对齐并合成PA；错误则走异常路径。成功后填入软件TLB。1GiB客体大页与这次4KiB软件缓存条目并不矛盾，它们属于两种不同粒度。

## 10. 一分钟开场

我们在Lab1启动基础上完成了物理内存管理。首先从DTB识别RAM，建立Page描述符并排除固件、内核、描述符和DTB占用；然后接入Best-Fit，课程评分20/20，同时补充碎片、耗尽和合并测试。进一步实现Buddy按二次幂分裂合并，以及页之上的简化SLUB对象缓存，并检查数据不重叠和所有页回收。分支任务中，我们构建独立带符号的QEMU，分别用客体GDB观察SATP和PTE，用宿主GDB观察真实取指、数据读的TLB未命中和页表查询。实测发现顶层是1GiB叶子，只需一次查表；数据地址0xffffffffc0206008被翻译为0x80206008。AI辅助实现、排错与整理，结论以实际日志和源码核对为依据。

| S模式 / 监管者模式 | Supervisor mode，通常用于操作系统内核；本实验uCore在此运行。 |
| U模式 / 用户模式 | User mode，通常用于普通应用。当前Lab2没有建立用户进程运行环境。 |
| 特权级 | 处理器对不同软件授予的操作权限等级；它不等于Windows文件权限。 |
| 固件 / firmware | 面向平台底层的软件，本次OpenSBI属于固件；通常在内核之前执行，也可继续提供运行时服务。 |
| SBI | Supervisor Binary Interface，S模式软件向底层执行环境请求服务的接口规范。 |
| OpenSBI | SBI的一种开源固件实现。本实验通过它启动S模式内核并输出字符。 |
| ecall / 环境调用 | RISC-V发起环境调用异常的指令。本实验由内核执行后交给OpenSBI处理SBI请求。 |
| 异常 / exception | 执行过程中需要特殊处理的事件，例如缺少可用页表映射；不一定意味着程序永远无法恢复。 |
| 中断 / interrupt | 来自定时器、设备等的事件，通常与当前执行的具体指令不是同步产生。 |
| 委派 / delegation | 把某些异常或中断交由较低特权级处理的配置机制。 |
| Boot ROM / 复位ROM | CPU启动时首先执行的一段固定代码；ROM为Read-Only Memory，只读存储器。QEMU模拟了本次0x1000处的复位代码。 |
| 引导程序 / bootloader | 将系统从初始状态带到内核运行的程序，可能读取镜像、准备参数并跳转。 |
| SPL | Secondary Program Loader，较小的早期引导程序，常初始化内存并加载后续程序。不是本次新增的内核代码。 |
| U-Boot | 一种常见引导程序，真实开发板可用它从存储介质加载内核；本实验直接启动路径没有执行U-Boot。 |
| UEFI | Unified Extensible Firmware Interface，统一可扩展固件接口。某些平台可通过其内存映射服务报告可用和保留内存。 |
| 初始化 | 在正式使用某个模块前设置它的初始状态，如清空空闲链表、建立描述符。 |
| 上下文切换 | 保存一份执行状态再恢复另一份执行状态，用于任务切换；本实验尚未实现调度。 |
| 系统调用 | 用户程序向内核请求服务的接口；不要把本实验内核向OpenSBI请求服务直接叫作用户系统调用。 |

## 二、内存、地址与计量

| 名词 | 含义与例子 |
| --- | --- |
| RAM | Random Access Memory，随机访问存储器，通常指运行程序使用的可读写内存。 |
| DRAM | Dynamic Random Access Memory，动态随机访问存储器，常用作主内存；本框架用DRAM_BASE标记其物理起点。 |
| 位 / bit | 二进制的一位，只能为0或1。 |
| 字节 / byte / B | 8位；物理地址通常按字节编号。 |
| KiB / MiB / GiB | 二进制容量单位，分别为1024字节、1024²字节、1024³字节。4KiB=4096字节，1GiB=1073741824字节。 |
| 十六进制 / 0x | 一种数值表示方法，每位表示4个二进制位。0x1000=4096；地址前的0x不是额外内存内容。 |
| 地址 | 某个存储位置的编号。地址大小与“这里存着多少字节”是不同概念。 |
| PA / 物理地址 | Physical Address，目标机器物理地址空间中的位置，供物理内存或设备访问。 |
| VA / 虚拟地址 | Virtual Address，程序发出的地址；开启分页后需要翻译才能得到PA。 |
| 地址空间 | 一组可用于寻址的地址及其解释规则。程序地址空间与物理RAM不必一一相同。 |
| 高地址内核 | 把内核放在很高的虚拟地址范围运行；本次0xffffffffc0200000对应物理0x80200000。 |
| 映射 / mapping | VA与PA之间的对应关系，不是再复制一份代码。 |
| 恒等映射 / identity mapping | VA数值与PA相同的映射；本次用于开启分页后短暂执行低地址代码。 |
| 偏移量 / offset | 两个位置之间的差值；本次内核线性映射使用固定VA-PA偏移。 |
| 页 / page | 地址空间按固定大小划分的单位；本次普通页为4096字节。 |
| 页框 / page frame | 一页大小的物理内存单元。为了区分虚拟页和物理页，物理页也常称页框。 |
| PPN / PFN | Physical Page Number / Page Frame Number，物理页号；本次PA右移12位得到PPN。 |
| VPN | Virtual Page Number，虚拟页号；Sv39又把它拆成VPN2、VPN1、VPN0三级索引。 |
| 页内偏移 | 地址在某页内部的位置，4KiB页的低12位。普通4KiB映射中翻译不改变该偏移。 |
| 连续物理页 | 物理页号连续的页，不只是描述它们的链表节点恰好相邻。 |
| 对齐 / alignment | 地址满足某个倍数条件。4096字节对齐指地址可被4096整除。 |
| ROUNDUP / 向上对齐 | 找到不小于当前值的最近对齐值。例如4100向4096对齐得到8192。 |
| ROUNDDOWN / 向下对齐 | 找到不大于当前值的最近对齐值。例如4100向4096对齐得到4096。 |
| 上界 / 区间 | 本文[起点,终点)包含起点但不包含终点，因此长度为终点-起点。 |
| 保留区 / reserved | 已被固件、内核、设备信息或管理结构占用，不能交给普通分配器的区域。 |
| DTB | Device Tree Blob，设备树的二进制文件，描述RAM和设备地址等硬件信息。 |
| FDT | Flattened Device Tree，扁平设备树，DTB采用的编码形式。这里只需理解为设备树的标准数据布局。 |
| memory节点 / reg属性 | 设备树用节点描述设备；memory节点的reg属性保存内存区间等信息。这里reg不是CPU寄存器。 |
| reserved-memory | 设备树中可描述保留内存的节点。本框架尚未完整解析所有这类区域。 |
| 字节序 / endian | 多字节数值按什么顺序存储；设备树整数字段采用大端格式，需要转成CPU可用的数值。 |
| 溢出 / overflow | 结果超出变量可表达范围而回绕等。例如base+size必须先检查是否溢出，不能仅看加法结果。 |
| MMIO | Memory-Mapped I/O，内存映射设备访问，通过物理地址读写设备寄存器；物理地址空间不全是RAM。 |
| UART / 串口 | Universal Asynchronous Receiver/Transmitter，通用异步收发器；本实验底层字符输出使用模拟串口。 |

## 三、分配器与C代码数据结构

| 名词 | 含义与本实验中的例子 |
| --- | --- |
| PMM | Physical Memory Management，物理内存管理；此处pmm_manager是一组页分配操作的接口。 |
| 分配器 / allocator | 管理可用空间，响应申请并处理归还的模块。 |
| Page描述符 | 记录一个物理页状态的C结构体。卡片占40字节，它描述的物理页占4096字节。 |
| 元数据 / metadata | 为管理其他数据而保存的信息，例如Page描述符和slab页头。 |
| 结构体 / struct | C语言把多个相关字段组织在一起的数据类型。 |
| 字段 / member | 结构体中的一项，如Page的flags、ref。 |
| 数组 | 同类型元素连续存放的集合；pages[i]是第i个Page描述符，索引从0开始。 |
| 指针 / Page * | 保存对象地址的变量；Page *表示指向Page结构体。它的数值不是被描述页的物理地址。 |
| 指针运算 | p+1表示移动一个指向对象的大小；Page *移动一次跨sizeof(Page)字节。 |
| NULL | 空指针常量，表示未指向有效对象；分配失败可返回NULL。 |
| size_t | 保存大小、数量的无符号整数类型；本项目定义为64位。必须结合接口判断单位是字节还是页。 |
| uintptr_t | 足以保存指针数值的无符号整数类型，本项目用于地址运算。 |
| uint64_t | 64位无符号整数，常用于寄存器和位标记。 |
| sizeof | C运算符，得到一个类型或对象占用的字节数。 |
| 链表 | 用指针连接节点的数据结构，不要求节点所在内存连续。 |
| 双向链表 | 每个节点可以找到前后节点。空闲块头通过page_link接入链表。 |
| 链表头 / 哨兵 | 用来统一处理空表、头尾插入的特殊节点；它本身不是一个可分配块。 |
| 地址有序 | 按所描述物理页的先后排列，方便查找相邻块。 |
| 空闲块 / block | 若干连续、尚未分配的页组成的区间。 |
| 块头 | 块的第一页对应的描述符，保存长度或阶数等信息。 |
| 分割 / split | 将大空闲块拆成申请部分和剩余部分。 |
| 合并 / coalesce | 将满足条件的空闲块组成更大的空闲块。 |
| First-Fit | 首次适应，按搜索顺序选第一块足够大的空间。 |
| Best-Fit | 最佳适应，选择所有足够大的块中最小的一块；不是全局最优的保证。 |
| 外部碎片 | 空闲总量不少，但分散在不连续的小块里，不能满足大连续请求。 |
| 内部碎片 | 已分配块中有一部分空间超过实际请求而浪费，如Buddy申请3页占4页。 |
| Buddy System | 伙伴系统，按二次幂块分裂、按同阶伙伴合并的算法。 |
| 阶 / order | Buddy块大小的指数；块含2^order页。 |
| 二次幂 | 2的非负整数次幂，如1、2、4、8、16。 |
| XOR / 异或 / ^ | 对每一位做运算：相同为0，不同为1。Buddy用它翻转对应阶的地址位来找伙伴。 |
| 递归合并 | 合并后继续尝试更大一阶伙伴；可用循环实现，不要求函数一定调用自身。 |
| Slab | 将一块底层内存划分成多个固定大小对象的管理单元，本实现一页一个slab。 |
| SLUB | Linux的一类slab对象分配器的名称；本实验仅实现其按大小缓存、页内对象链和空页回收的主体思路，不硬按字母编造全称。 |
| 对象 / object | 一次分配交给调用者使用的那段空间，例如32字节数据区；这里不是专指面向对象语言的类实例。 |
| 大小类 / size class | 将相近请求统一到固定大小，如17～32字节进入32字节类。 |
| 对象缓存 / cache | 这里指保存可复用同类对象的管理结构，不是CPU硬件数据缓存。 |
| 空闲对象链 | 把尚未使用的对象连接起来，分配时摘下一个，释放时挂回一个。 |
| 内嵌指针 | 将next指针存进空闲对象自己的前几个字节，减少额外管理空间。 |
| magic / 魔数 | 元数据中约定的固定值，用于粗略识别结构类型或破坏，不是加密或完整安全校验。 |
| 回收 / reclaim | 对象不再使用时归还到缓存，或整页空闲后归还到底层页分配器。 |
| 内存泄漏 | 已经不再使用的空间没有归还，导致可用空间逐渐减少。 |
| 重复释放 / double free | 同一分配对象在未再次分配前被归还两次，会破坏管理状态。 |
| 越界 | 访问超过合法对象或数组范围的位置。 |
| per-CPU cache | 每个CPU各自拥有的缓存，减少共享竞争；本教学实现没有实现它。 |
| 并发 / 多核同步 | 多条执行流可能同时操作共享结构，需要保证操作不相互破坏。 |
| 无锁快路径 | 通过原子操作等机制让常见操作不获取传统锁；本实现没有宣称具备该能力。 |
| 断言 / assert | 检查某条件必须成立，失败则报告并停止正常执行；不是忽略错误后继续。 |
| panic | 内核遇到无法继续处理的问题时报告错误并停止正常流程，本项目随后循环。 |
| 边界测试 | 检查尺寸类切换、零长度、极限容量等容易出错的边缘。 |
| 隔离池测试 | 暂时将一小块空间与其他空闲内存分开，以可控状态验证耗尽和合并；结束后恢复原状态。 |
| O(k) | 时间复杂度表达：工作量大致随k增长；这里k为空闲块数量，不是一个固定耗时。 |

## 四、页表与地址翻译

| 名词 | 含义与本实验中的作用 |
| --- | --- |
| MMU | Memory Management Unit，内存管理单元，按规则将地址翻译并检查权限；真实机器通常由硬件实现，QEMU用代码模拟。 |
| 分页 / paging | 按页建立虚拟地址到物理地址映射的机制，与内存分配器按页分配是相关但不同的事情。 |
| Sv39 | RISC-V的39位虚拟地址分页方案：9+9+9位页表索引，12位普通页偏移，最多三级查找。 |
| Bare模式 | 不启用对应页表翻译的地址模式；satp的MODE为0。并不表示QEMU不用自己的软件访问缓存。 |
| SATP / satp | Supervisor Address Translation and Protection，监管者地址翻译与保护寄存器，保存翻译模式、ASID和根表物理页号。 |
| MODE字段 | SATP中指定翻译方案的位段。本次MODE=8为Sv39，0为Bare。 |
| ASID | Address Space Identifier，地址空间标识符，可辅助区分不同地址空间的缓存翻译；本次为0。 |
| PTE | Page Table Entry，页表项，一条映射或下级表地址记录；本次每项8字节。 |
| 根表 / 顶层页表 | 翻译时最先查询的一张页表，基址来自SATP。 |
| 多级页表 | 顶层项可指向下一张页表，按地址中不同索引逐层查询。 |
| 索引 / index | 在数组或页表中选第几项的编号；Sv39每级索引9位，范围0～511。 |
| 叶子PTE | 直接给出物理页或大页映射的项，不再指向下级表。本实验根表项已经是叶子。 |
| 非叶子PTE / inner PTE | 指向下一级页表的项，处理器继续读取下一层。 |
| 大页 / superpage | 高于普通4KiB粒度的映射；Sv39中间层叶子可映射2MiB，顶层叶子可映射1GiB。 |
| 页表遍历 / page walk | 从根表开始，计算索引、读取PTE、判断叶子或继续下一层的过程。 |
| 访存 | 访问存储，包括指令读取、数据读取和数据写入。不是只有C代码中的显式赋值才算。 |
| 取指 / instruction fetch | 读取CPU接下来执行的机器指令，也是需要地址翻译的访问。 |
| load / 数据读 | 从内存读出数据，RISC-V的ld一次读取8字节。 |
| store / 数据写 | 把数据写入内存，RISC-V的sd一次写入8字节。 |
| 权限检查 | 判断该模式和访问类型能否读取、写入或执行对应页面。 |
| V/R/W/X/U/G/A/D | PTE标记：有效、可读、可写、可执行、用户页、全局、已访问、已脏。 |
| 已脏 / dirty | 页面被写入的相关状态标记；本启动映射预置D=1。不是说数据“损坏”。 |
| 页故障 / page fault | 翻译不合法、权限不允许等引起的异常；并不总是物理内存坏了。 |
| 符号扩展 | 把较窄有符号数扩展成较宽位数时，使用原最高符号位填充高位；Sv39有效高地址需要满足相关规范。 |
| sfence.vma | RISC-V同步地址翻译状态的指令，配合页表更新使后续翻译一致；不等于清空RAM或全部CPU缓存。 |
| TLB | Translation Lookaside Buffer，地址翻译后备缓冲，缓存最近的地址翻译及权限信息，减少重复查页表。 |
| TLB hit / 命中 | 访问需要的翻译已在缓存中，可以使用它。 |
| TLB miss / 未命中 | 需要的可用翻译不在当前缓存中，需要进一步处理，如查询备用缓存或页表。 |
| TLB标签 / tag | 用来识别某缓存项对应哪个地址范围及上下文的信息。 |
| victim TLB | QEMU中辅助保存近期从主缓存替换出的条目的缓存；victim不是用户程序里的“受害进程”。 |
| TLB填充 / fill | 成功获得翻译后将结果存入缓存。 |
| 缓存失效 / invalidate | 让旧缓存结果不再被使用，避免页表变化后沿用旧映射。 |
| 客体物理地址 | 被模拟机器认为的物理地址；在QEMU内部仍需对应到宿主存储空间，不能直接当宿主进程指针。 |
| 两阶段翻译 | 虚拟化中客体地址可能经两个架构阶段转换；本实验记录的是普通单阶段S模式路径。 |

## 七、公式与符号别误解

- `>>`、`<<`：二进制右移、左移。对这里的无符号页地址，右移12相当于去掉页内偏移；左移12相当于页号乘4096。
- `&`：在算式里是按位与，用掩码保留特定位；在`&kern_init`中则是C的取地址运算，两种用法应结合上下文。
- `|`：按位或，把不同位段组合起来，例如MODE与PPN。
- `^`：按位异或，用于定位Buddy伙伴。
- `0x1ff`、`511`：前者是十六进制，二者相等；9位全为1，用来提取一级VPN索引。
- `0xfffffffffff`：低44位为1的掩码，用来提取本实验RV64 SATP的根表PPN。
- `ceil`、`floor`：数学上的向上取整、向下取整，不是一定调用了这两个C库函数。
- `~`：按位取反；公式中的全1上界可由无符号类型的取反得到。Shell路径中的`~`则表示家目录，含义不同。
- `->`、`.`：通过结构体指针/结构体对象访问字段；不是两种不同物理地址。
- `>=`、`==`、`NULL`：大于等于、判断相等、空指针；`=`则是赋值。
