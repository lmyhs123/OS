# Lab2 现场演示命令与逐项含义

实验代码：Ubuntu `/home/lmy/os/lab2`；Windows `Z:\home\lmy\os\lab2`。以下命令在Ubuntu中执行。GDB命令一条一条输入，`(gdb)`是提示符，不用输入。先关闭上一次手动演示的QEMU，避免占用1234端口。

## 1. 构建、运行、评分

```bash
cd ~/os/lab2
export PATH=/home/lmy/riscv-elf-toolchains/bin:$PATH
make clean
make -j4
make qemu
```

看见 `[Best-Fit] ... PASS`、`check_alloc_page() succeeded!`、`[SLUB] ... PASS`。最后无限循环是预期行为。按Ctrl+A，松开，再按X退出QEMU。

```bash
make grade
```

预期最后 `Total Score: 20/20`。该评分只覆盖课程page_init和Best-Fit两项；Buddy/SLUB有单独测试，不能说课程评分覆盖了所有扩展。

| 命令/参数 | 含义 |
| --- | --- |
| cd ~/os/lab2 | 切换工作目录；~是当前用户家目录 |
| export PATH=...:$PATH | 把工具链bin目录放到命令搜索路径前面，保留原路径；只影响当前Shell及其子进程 |
| make | 读取Makefile，根据依赖构建默认目标 |
| clean | Makefile中的清理目标，删除obj/bin，保留源码、报告、日志 |
| -j4 | 最多4个构建任务并行；不是4个客体CPU |
| qemu | 构建镜像并启动系统模拟器 |
| grade | 复制代码至临时目录、注入课程测试、构建运行并检查输出 |

## 2. 展示Buddy（切换配置必须先clean）

```bash
make clean
make PMM=buddy -j4
make PMM=buddy qemu
```

预期manager为buddy_pmm_manager，Buddy和SLUB均PASS。PMM是Make变量，buddy启用-DPMM_BUDDY编译分支。三页请求实际占四页，释放传原请求3。

退出后恢复默认：

```bash
make clean
make -j4
```

## 3. 展示RAM变化（可选）

```bash
qemu-system-riscv64 -machine virt -m 64M -nographic -bios default -kernel bin/ucore.img
```

`-m 64M`给模拟机器64MiB RAM。256M也能启动，但管理上界受框架PHYSICAL_MEMORY_END限制；DTB报告的总量与实际受管量要分别解释。

## 4. 客体内核GDB，两个终端

终端A：

```bash
cd ~/os/lab2
make debug
```

终端B：

```bash
cd ~/os/lab2
gdb-multiarch -q bin/kernel
```

GDB逐条输入：

```gdb
set pagination off
target remote :1234
info registers pc satp
x/6i $pc
hbreak kern_init
continue
info registers pc satp sp
p/x &boot_page_table_sv39
set $rootpa = ($satp & 0xfffffffffff) << 12
p/x $rootpa
set $va = (unsigned long)&kern_init
p/x ($va >> 30) & 511
x/gx $rootpa+511*8
x/gx $rootpa+2*8
x/6i $pc
```

实测SATP=0x8000000000080205，根表PA=0x80205000，第511项和第2项PTE=0x200000cf。第511项是高地址映射，第2项是低地址过渡映射。`hbreak`使用硬件辅助断点，适合尚未建立高地址映射时设置高地址入口断点。

结束：

```gdb
detach
quit
```

再到A用Ctrl+A、X退出。若只想复现并打印已验证的观察，可运行自动脚本（独立占用1235）：

```bash
python3 tools/verify_guest.py
```

## 5. 分支任务：宿主GDB调QEMU，客体GDB驱动执行

先确保恢复默认Best-Fit构建。调试版QEMU及源码已在这台虚拟机编好，不需sudo。它是普通x86-64程序，因此用普通gdb调试；客体仍用gdb-multiarch。

### 最稳妥的自动演示

```bash
cd ~/os/lab2
export PATH=/home/lmy/riscv-elf-toolchains/bin:$PATH
python3 tools/verify_host.py
python3 tools/verify_host.py boot_dtb
```

第一条脚本演示内核入口取指，第二条演示真实8字节数据读取。脚本自动启动宿主GDB及QEMU，另一客体GDB连接1236端口并continue；条件断点记录关键状态后主动kill它自己创建的QEMU，打印HOST_TRACE_COMPLETE。这不是内核崩溃；脚本验证通过才正常返回。输出和命令保存于evidence。脚本通过nm动态查询目标符号地址，较手写地址更适合修改代码后重演。

### 手动单步演示

终端A（宿主GDB兼QEMU控制台）：

```bash
cd ~/os/lab2
gdb -q -x tools/manual-host.gdb --args /home/lmy/oslab-tools/qemu-ubuntu-build/qemu-system-riscv64 -L /usr/share/qemu -machine virt -nographic -bios default -kernel bin/ucore.img -gdb tcp:127.0.0.1:1234 -S
```

终端B（客体GDB）：

```bash
cd ~/os/lab2
gdb-multiarch -q bin/kernel
```

```gdb
target remote :1234
hbreak kern_init
continue
```

在高地址入口停下后可显示PC/SATP，再继续：

```gdb
info registers pc satp
continue
```

随后A会命中boot_dtb读的TLB填充断点，B等待属于正常状态。此时转到A依次操作：

```gdb
bt 5
p/x address
p access_type
continue
```

A第二次停在get_physical_address：

```gdb
p/x addr
p/x env->satp
p is_debug
continue
```

A第三次停在PTE读取后：

```gdb
p i
p ptshift
p/x base
p/x pte_addr
p/x pte
continue
```

A第四次停在tlb_set_page之前：

```gdb
p/x address
p/x pa
p prot
p/x tlb_size
```

应看到VA=0xffffffffc0206008、PA=0x80206008、PTE=0x200000cf、i=0、ptshift=18、prot=7。说明顶层1GiB叶子完成转换，QEMU此次软件缓存粒度为4KiB。

结束时在A执行 `kill`、`quit`，B断开后quit。正常结束可能出现远端关闭信息。若修改代码使符号地址变化，先用下面命令查看，再更新manual-host.gdb内的地址；源码版本变化也需重新核对断点行号。自动脚本的符号地址会自行更新。

```bash
riscv64-unknown-elf-nm bin/kernel | rg 'kern_init|boot_dtb|boot_page_table'
```

如Ubuntu没有rg，可将最后一段改为 `grep -E 'kern_init|boot_dtb|boot_page_table'`。

## 6. QEMU和宿主GDB参数详解

| 参数 | 含义 |
| --- | --- |
| qemu-system-riscv64 | 模拟完整的64位RISC-V机器，不是用户态qemu-riscv64 |
| -machine virt | 选择通用虚拟机器型号 |
| -nographic | 无图形显示，串口/监视交互进入终端 |
| -bios default | 使用配套默认OpenSBI |
| -kernel bin/ucore.img | 加载内核并构建下一阶段信息 |
| -L /usr/share/qemu | 调试版从系统QEMU数据目录寻找固件资源 |
| -S | 客体CPU启动后先暂停 |
| -s | QEMU的简写调试监听，默认1234；手动宿主命令改用显式-gdb |
| -gdb tcp:127.0.0.1:1234 | 在本机回环端口提供客体调试接口 |
| gdb -q | 启动宿主调试器，减少欢迎文字 |
| -x tools/manual-host.gdb | 读取预设GDB命令与条件断点 |
| --args | 后面是被调试程序及其参数，不是GDB自身参数 |
| handle SIGPIPE nostop noprint pass | 遇到管道信号不暂停、不打印，仍交给目标处理 |
| handle SIGUSR1 ... | 同理，避免QEMU内部唤醒信号频繁打断调试 |

## 7. GDB命令和表达式逐项解释

| 命令 | 含义 |
| --- | --- |
| target remote :1234 | 连接本机QEMU的客体GDB接口 |
| info registers pc satp sp | 当前执行地址、页表控制寄存器、栈指针 |
| x/6i $pc | 从PC指向内存开始反汇编6条机器指令；i表示指令 |
| p/x &符号 | print，以十六进制显示符号地址；&取地址 |
| x/gx 地址 | examine，读取一个8字节单位(g)，以十六进制(x)显示 |
| set $rootpa=... | 设置GDB临时变量，不是修改内核全局量 |
| satp & 0xfffffffffff | 提取低44位根表物理页号 |
| << 12 | 页号乘4096，得到页基址 |
| (VA >> 30) & 511 | 获取Sv39最高层VPN2，宽9位 |
| 根表地址+511*8 | 512项根表中第511项的地址，每项8字节 |
| b 函数 if 条件 | 条件满足才暂停，减少无关地址转换 |
| bt 5 | 显示最多5层调用栈 |
| p/x env->satp | 打印QEMU的客体CPU状态结构中的SATP |
| si / si 4 | 执行1条/4条目标机器指令；宿主GDB中目标是x86 QEMU，客体GDB中目标是RISC-V内核 |
| next / step | 按C源码行执行，next尽量跨过函数，step可进入函数 |
| continue | 放行至下一断点或人工暂停 |
| detach | 断开并通常放行目标 |
| kill | 终止当前被调试进程，宿主这里指QEMU |
| quit | 退出当前GDB |

## 8. 源码关键编译参数

`-march=rv64gc`指定64位RISC-V通用扩展及压缩指令；`-mabi=lp64d`指定对应调用约定；`-mcmodel=medany`让代码支持适合内核布局的PC相对寻址。`-std=gnu99`使用GNU C99；`-O2`优化；`-g`保留调试信息；`-Wall`启用常用警告；`-Werror`把警告当错误；`-Wno-unused`抑制未使用项警告。`-nostdinc`不搜索宿主标准头文件；`-fno-builtin`不把本地字符串函数当宿主内建替换；`-fno-stack-protector`不依赖尚未实现的运行时栈保护；`-ffunction-sections/-fdata-sections`细分section；链接`--gc-sections`丢弃未引用section，`-nostdlib`不链接标准库，`-T tools/kernel.ld`使用内核链接脚本，`-m elf64lriscv`指定链接格式。

调试QEMU的`--enable-debug`启用符号及调试配置；`--target-list=riscv64-softmmu`仅构建所需系统目标；`--disable-install-blobs`避免Ubuntu去掉的固件安装资源导致配置失败；`--disable-docs/--disable-tools/--disable-pixman`减少无关依赖；`--disable-werror`不将上游/宿主版本差异警告作为编译错误。没有make install，运行时显式调用新二进制。
